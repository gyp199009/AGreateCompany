# 00 · 公司命题（Thesis）

> 使命：**让"发现"发生的速度提升一个数量级，并让这个过程对所有人可见、可核验、可复现。**

这句话是全文的约束条件。后面所有的产品方向、技术选型、指标设计，都要能被这句话检验：它是在让"发现"变快，还是在让"看起来像发现"变多？

---

## 1. 我们相信什么（Beliefs）

以下五条是我们的判断，不是事实。每条都附了"如果它错了会怎样" —— 这是本文件最重要的部分。

| # | 信念 | 如果错了 |
|---|---|---|
| B1 | **瓶颈已从"生成"转向"验证"。** 模型已经能产出远超人类消化速度的假设、代码与综述草稿；稀缺的不再是想法，而是判断哪个想法值得花三个月去验证。【判断】 | 若验证成本本身被模型大幅降低（自动实验闭环成熟），我们的价值重心要从"证据整理"转向"实验调度"。 |
| B2 | **在专业场景里，可信度是可计价的产品属性，不是合规成本。** 研究者愿意为"每条断言都能点到源头"多付 10 倍价钱，但不会为"更流畅的答案"多付一分。【判断】 | 若用户实际只在乎速度，我们应转向极简、极快的轻量工具，放弃重证据链路（会显著缩小团队与估值空间）。 |
| B3 | **人类知识里最贵的部分是"矛盾"。** 同一问题下的冲突证据、失败实验、阴性结果，是现有搜索引擎结构性丢弃的资产。【判断】 | 若冲突检测的准确率长期无法超过专家直觉，它就只能作为提示功能，不能作为核心卖点。 |
| B4 | **科学数据正在足够开放。** 开放获取、预印本、结构数据库、试验注册库的覆盖度足以支撑冷启动。【待验证：需按领域逐个实测覆盖率】 | 若目标领域开放语料覆盖率 < 60%，就必须先做数据合作，产品节奏整体后移 1–2 个季度。 |
| B5 | **小团队 + 强评测可以打赢大团队 + 强模型。** 领域评测集与证据图谱是复利资产，模型能力是外部变量。【判断】 | 若前沿模型把"证据链"原生做进推理（并免费），我们必须靠私有数据与工作流深度护城。 |

## 2. 我们不做什么（Non-goals）

明确写下不做的事，比写下要做的事更能定义公司。

- **不做通用聊天助手。** 没有领域、没有工作流、没有评测的对话产品，我们无法形成任何复利。
- **不代写论文、不代做同行评审。** 这会摧毁我们唯一想积累的东西：可信度。
- **不在 24 个月内做临床诊断或治疗决策。** 监管与责任结构不匹配，且会拖垮整个工程节奏。
- **不训练基础大模型。** 我们是在模型能力之上做"验证层"，不是与之竞争。
- **不追求"全学科覆盖"。** 前 18 个月只做 1–2 个领域，深度优先于广度。
- **不做双用途（dual-use）能力的不设限开放。** 见 `04-risks-and-open-questions.md` 的生物安全条款。

## 3. 北极星指标（North Star）

> **NSM：每周被研究者采纳、并进入下一步动作的「可核验假设」数量。**
> （Verified-usable hypotheses adopted per week）

三个词都是硬约束，缺一不可：

- **可核验**：该假设涉及的每条关键断言，都能在证据图谱中点到具体来源（文献段落 / 试验记录 / 客户内部文档），且系统给出的支持度可被独立复核。
- **被采纳**：用户在系统里显式标记为「进入验证 / 纳入方案 / 转给同事」，而不是"看过了"。
- **假设**：是"若 X 则 Y，可通过 Z 检验"的形式，不是一段综述文字。

配套的**反指标（guardrails）**——它们变好时我们应当警惕：

| 反指标 | 警戒含义 |
|---|---|
| 无来源断言率 | > 2% 即触发发布阻断（任何输出中的事实性断言必须有来源或明确标注"推测"） |
| 专家抽检驳回率 | 上升说明我们在用流畅度冒充正确性 |
| 单次会话时长 / 采纳数 | 时长上升而采纳数不变 = 用户在替我们做验证工作 |
| 用户对输出的整段复制率 | 整段复制 = 我们把思考外包了，长期损害用户能力与我们的口碑 |
| 单位采纳成本（USD / adopted hypothesis） | 成本失控会让"价值"变成"奢侈品" |

## 4. 工程原则（Engineering Principles）

1. **Provenance-first。** 数据模型的第一等公民是"这句话从哪来、谁提取的、置信度多少、何时失效"，而不是"这句话是什么"。
2. **一切可复现。** 任何一次输出都能用 `run_id` 还原：数据快照版本 + 模型版本 + 提示版本 + 工具调用轨迹 + 随机种子。
3. **会弃权（abstention）。** 系统说"证据不足"必须和给出答案一样容易，且在 UI 上同等体面。
4. **人在环是设计，不是免责声明。** 每个自动流程都要指定人类审批点，且审批点要设计得让人愿意真的看。
5. **度量公开。** 我们对外发布自己的评测方法与失败案例，就像发布产品功能一样。
6. **最小权限 + 数据主权。** 客户数据不用于训练共享模型（除非显式授权），区域化存储，退出即删除。

## 5. 三年后的样子（如果一切顺利）

- 一个领域（例如神经退行性疾病、或某个材料子领域）的研究者，把我们的工作台当作默认起点，就像今天把 PubMed + Excel + 组会当作默认起点。
- 我们公开的**证据图谱**与**评测基准**被其他团队引用为标准参考——这是比用户数更强的护城河。
- 至少 3 个由平台辅助产生的、进入湿实验验证的假设被独立团队复现成功。
- 收入足以自负盈亏，且不需要靠"降低证据标准"来换增长。

如果三年后我们只有一个漂亮的对话界面和一个增长曲线，那说明这件事我们做错了。
