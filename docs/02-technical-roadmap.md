# 02 · 技术路线

> 一条原则贯穿全文：**我们不生产答案，我们生产"可被检验的答案 + 它的边界"。**
> 所有架构决策都可以用这一句话来裁决。

---

## 1. 五个技术论点（Technical Theses）

这五条决定了我们和"套壳 RAG"的根本区别。

| # | 论点 | 反直觉之处 | 对应设计 |
|---|---|---|---|
| T1 | **检索不是产品，证据链才是。** | 提升检索指标（recall@k）常常不改善最终可信度；真正起作用的是"断言 → 证据 → 判定"的结构 | Claim-Evidence 三阶段管线 |
| T2 | **让模型少说，让验证器多说。** | 把生成模型的能力主动往下压，用独立的验证器（小模型 + 规则）复核，准确率反而上升 | Verifier-first，生成器不能自评 |
| T3 | **弃权是特性，不是失败。** | "我不知道" 的 UI 质量决定用户信任 | 三态输出 + 覆盖率指标 |
| T4 | **可复现性是工程约束，不是合规负担。** | 从第一天就记录 run 五元组（数据/模型/提示/工具/随机性），后期能省掉 80% 的 debug 成本 | Run Ledger |
| T5 | **评测集是资产，模型不是。** | 花 3 个月建 3000 条专家标注数据，比换一个更强的模型更有价值 | Evals as Product |

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────────────────┐
│  交付层  Workbench(Web) · Report Studio · API · 私有化部署包               │
├──────────────────────────────────────────────────────────────────────────┤
│  编排层  Agent Runtime：Temporal durable workflow · 沙箱执行 · HITL 审批门  │
│         预算/步数控制 · 轨迹记录（run 五元组）                              │
├──────────────────────────────────────────────────────────────────────────┤
│  推理层  Claim 分解 → 逐条证据检索 → 蕴含/反驳判定 → 冲突聚类 → 置信校准      │
│         Verifier Ensemble（小模型 + LLM judge + 确定性检查）                │
├──────────────────────────────────────────────────────────────────────────┤
│  检索层  Hybrid(BM25 + dense) → 图谱扩展(2-hop) → Cross-encoder rerank     │
│         段落级锚定 chunk（稳定 offset，指向原文位置）                       │
├──────────────────────────────────────────────────────────────────────────┤
│  知识层  本体对齐(MeSH/ChEBI/GO/HGNC…) · 实体链接 · 双时态图谱 · 版本快照    │
├──────────────────────────────────────────────────────────────────────────┤
│  数据层  Ingestion → Bronze(原文) → Silver(结构化段落/表/图注) → Gold(断言)  │
│         Iceberg 表 + 对象存储 + 全链路 lineage                              │
├──────────────────────────────────────────────────────────────────────────┤
│  平台层  多租户 · RBAC/ABAC · SSO/SCIM · 审计 · 配额 · 成本归因 · OTel 观测  │
└──────────────────────────────────────────────────────────────────────────┘
```

**关键结构选择：把"推理"和"检索"彻底分开，中间用结构化对象（Claim / Evidence / Verdict）通信。** 这样生成模型可以随时替换，评测可以在每一层单独做，出错时能定位到是"没找到"还是"看到了却判断错"。

## 3. 核心链路：一张 Claim Card 是怎么产生的

```
用户问题
  │
  ├─(1) 问题理解：领域识别、概念消歧、意图分类（找证据 / 找空白 / 找冲突 / 设计方案）
  │
  ├─(2) Claim 分解：把问题拆成 1–7 条原子命题（可独立证伪的最小单位）
  │       每条命题标注：主体 / 干预 / 比较 / 结局 / 人群 / 条件
  │
  ├─(3) 每条命题独立检索：正文视图 + 摘要视图 + 图谱邻居视图（三路召回，合并去重）
  │
  ├─(4) 证据抽取：把候选段落转成结构化 Evidence
  │       {方向:支持/反驳/中性, 研究类型, 样本量, 物种, 剂量, 结局, 段落原文, offset}
  │
  ├─(5) 判定：Verifier 对该 Evidence 与 Claim 的关系给出三态判定 + 置信
  │       ⚠️ 生成器不得参与自身输出的判定（T2）
  │
  ├─(6) 聚合：按证据强度加权（研究类型 × 样本量 × 直接性 × 一致性）→ 置信等级 A/B/C/D
  │       并显式列出：冲突点在哪一层、缺什么证据才能升级
  │
  ├─(7) 渲染：Claim Card（三态 UI）+ "我们还不知道什么" + 可导出证据矩阵
  │
  └─(8) Run Ledger：记录本次全部中间产物（可回放、可对比、可审计）
```

**阶段 (5) 是整个技术的护城河所在。** 它不是"再问一次大模型"，而是：

- **确定性检查先行**：数值一致性、单位、时间先后、人群匹配（规则能抓住的错误，绝不留给小模型）。
- **小模型做关系判定**：fine-tune 一个 1–7B 的 cross-encoder 判断 (claim, evidence) 的蕴含/反驳，成本低、可本地部署、可控。
- **大模型只做困难样本与解释生成**：在不确定区（0.35 < p < 0.65）调用，并且必须给出理由。
- **投票与弃权**：三者不一致时输出"证据存在分歧，建议人工核验"，并把这个样本自动加入标注队列（**主动学习闭环**）。

## 4. 技术选型与理由

选型标准：**能少一个组件就少一个**；在 10 人团队规模下，运维复杂度就是最大的技术风险。

| 层 | 选择 | 为什么 | 替代方案 / 何时重新评估 |
|---|---|---|---|
| 应用后端 | Python 3.12 + FastAPI | 与 ML 生态同语言，团队认知负担最低 | 高并发网关层可加 Go；暂不需要 |
| 工作流 | **Temporal** | 长任务（解析 500 篇 PDF、跑 20 步 agent）必须可恢复、可重试、可观测；自研状态机是经典债务陷阱 | 若云厂商绑定过重，评估 AWS Step Functions |
| 关系库 | **Postgres** | 事务 + JSONB + 全文检索 + 权限模型一库搞定 | — |
| 向量 | **pgvector**（起步） | 单库、零额外运维；10M 段落以内完全够 | 超过 ~50M chunk 或需强过滤时，评估 Qdrant / Turbopuffer |
| 图 | **Postgres 邻接表 + 递归 CTE**（起步） | 我们的查询以 2-hop 为主，图数据库的收益被运维成本抵消 | 出现 ≥4-hop 频繁查询或图算法需求时迁 AGE/Neo4j |
| 语料湖 | **S3 兼容 + Apache Iceberg** | 版本快照、时间旅行、廉价存算分离；语料会到 TB 级 | — |
| 转换 | **dbt**（Silver/Gold） | 数据质量可测、可回归 | 起步期可用 SQL 脚本，但 3 个月内上 dbt |
| PDF 解析 | **GROBID** + 版面模型兜底 | 学术 PDF 解析的开源最优解；失败样本必须可视化人工修 | 评估商业解析 API 作为长尾兜底 |
| 模型 | **多模型路由 + 可替换抽象层** | 不绑定单一供应商；按任务选价（判定用小模型、生成用大模型） | 每季度重跑一次模型替换评测 |
| 嵌入 | 开源可自托管（bge/e5 系列）+ 商业 API 双轨 | 私有化部署是 B 端硬需求 | — |
| 沙箱 | **Firecracker / gVisor 隔离容器**，默认断网 | Agent 会执行代码；默认禁网是唯一能睡好觉的设置 | 前期可用托管沙箱服务加速 |
| 前端 | Next.js + TypeScript | 表格/编辑器/引用定位这类交互需要强类型 | — |
| 基础设施 | Kubernetes + Terraform + ArgoCD | 私有化交付需要可复制的部署包；IaC 是私有化的前提 | 早期单机 Docker Compose 也能活，但要留好迁移路径 |
| 观测 | OpenTelemetry + 结构化事件（每次 run 一条 trace） | 可复现性（T4）的落地载体 | — |
| 评测 | 自建 harness（轻量）+ 外部基准对齐 | 领域评测没有现成工具 | 可借力 Inspect/promptfoo 的接口约定 |

**统一的抽象层（最重要的一条）**：所有模型调用必须经过内部 `ModelGateway`（统一幂等、重试、成本计量、缓存、审计、A/B）。禁止业务代码直接 import 任何厂商 SDK。这一条能让我们在半年内不被任何一家供应商锁死。

## 5. 数据战略

**语料来源（按获取难度排序）**

| 类别 | 来源 | 风险 |
|---|---|---|
| 开放获取全文 | PMC OA、arXiv、bioRxiv/medRxiv、DOAJ、Unpaywall 定位 | 覆盖率因领域而异（见 H3） |
| 元数据 & 引用网络 | OpenAlex、Crossref、PubMed | 稳定，可做引用图谱 |
| 结构 / 通路 / 本体 | PDB、UniProt、ChEMBL、GO、MeSH、HGNC | 需要映射与版本管理 |
| 试验与监管 | ClinicalTrials.gov、EU CTR、FDA/EMA 公开文档 | 半结构化，抽取成本高 |
| 专利 | USPTO、EPO OPS（与商业专利数据商合作） | 许可与费用 |
| 客户私有 | ELN、S3、Confluence、SharePoint、测试数据库 | 权限模型与数据隔离 |

**三条铁律**

1. **不建影子图书馆。** 只用开放获取、客户自带、或已授权语料。这不只是法律问题：一旦越线，B 端与机构合作全部关闭。
2. **每个段落必须可回指。** 存原文 + 稳定 offset + 文档版本 hash；重新解析时旧断言自动标记"待复核"，而不是悄悄漂移。
3. **双时态（bitemporal）。** 同时记录"这个事实在世界上何时成立"和"我们何时知道它"——科学结论会翻案，我们的系统必须能表达"2023 年我们认为 X，2025 年证据推翻"。

**数据质量门槛（进入 Gold 层前必须过）**

- 段落切分完整率（未被截断）≥ 99.5%
- 实体链接准确率（抽样）≥ 95%
- 章节角色识别（方法/结果/结论）≥ 97%
- 同一文档重复摄取率 0（幂等键 = DOI + 版本 + 内容 hash）

## 6. 评测体系（Evals as Product）

**没有评测的 AI 产品，等于没有测试的数据库。**

### 6.1 分层指标

| 层 | 指标 | 目标（Phase 2） |
|---|---|---|
| 检索 | 关键证据召回率 / 段落定位准确性 | ≥ 85% / ≥ 99%（定位必须准，否则"点击溯源"就废了） |
| 抽取 | Evidence 字段填充正确率（方向、样本量、研究类型） | ≥ 93% |
| 判定 | 三态判定 F1（支持/反驳/中性） | ≥ 0.88 |
| 校准 | 置信等级与真实正确率的偏差（ECE） | ≤ 0.06 |
| 弃权 | 该弃权时弃权率 / 不该弃权时误弃权率 | ≥ 90% / ≤ 8% |
| 端到端 | 专家盲评"可用"率 | ≥ 80% |
| 成本 | 单张 Claim Card 推理成本 | ≤ $0.35 并逐季下降 |

### 6.2 工程机制

- **Golden Set 版本化**：起始 800 条专家标注断言，每季度 +500；每条含"专家判定 + 判定理由 + 难度标签"。
- **发布门禁**：任何提示词 / 模型 / 阈值变更必须跑全量评测；关键指标回退 > 2% 直接阻断合并。
- **对抗集**：专门收集"看起来对但错"的样本（相关但非因果、物种外推、剂量误读、时间倒置）——这是最容易被通用模型骗过的地方。
- **在线-离线闭环**：用户点"这条不对"→ 进入标注队列 → 进入下一轮 golden set。这个 flywheel 的转速就是我们的学习速度。
- **公开报告**：每半年发布一次评测方法与失败模式清单（`Model & Evidence Card`）。

## 7. Agent 运行时（我们真正的"产品基础设施"）

自动化科研不是一次性问答，而是**长跑**。运行时设计决定我们能不能做"重活"。

| 能力 | 设计 |
|---|---|
| 持久化 | Temporal workflow；崩溃恢复后从最后一个成功步骤继续，不重跑全流程 |
| 预算 | 每次 run 有 token / 金额 / 步数 / 时长四重上限，超限优雅降级并告知用户 |
| 沙箱 | 代码与数据处理在无网络容器内执行；文件系统只读挂载输入，输出走 artifact store |
| 人工审批门（HITL） | 三类动作必须审批：对外发送、写回客户系统、消耗 > 预算阈值。审批界面显示"将要发生什么"的 diff |
| 可观测 | 一个 run = 一条 trace；每一步有输入/输出/成本/耗时；支持"从第 5 步分叉重跑" |
| 可比较 | 同一问题的两次 run 可 diff（证据集变化、判定变化），这是"结论翻案"的产品化 |
| 安全 | 工具白名单；提示注入防护（外部文档中的指令一律视为数据，不视为指令）；输出过滤 |

## 9. 分阶段技术路线

### Phase 0 · 打通一条链（0–3 月）

**目标**：证明"断言级证据"在**一个真实领域**里能被专家接受。

- 交付：单机部署的管线（摄取 5k 篇 → 证据图 → Claim Card → 导出），无多租户、无 UI 打磨，内部 + 10 位设计伙伴可用。
- 技术重点：PDF 解析质量、Claim 分解、Verifier v0（规则 + 单模型）、Run Ledger。
- **退出标准**：200 条断言盲评，对齐正确率 ≥ 90%；单卡成本 ≤ $1.5；端到端 P95 < 90s。
- **风险**：领域选错。缓解——在第 1 个月就用 H3 实测两个候选领域的语料覆盖率，选高的那个。

### Phase 1 · 产品化（3–9 月）

**目标**：从"能跑"到"别人能用、能付钱"。

- 交付：多租户 SaaS、Workbench v1、3 个数据源家族、评测门禁进 CI、SOC 2 准备启动、生物安全拦截上线。
- 技术重点：Temporal 化、pgvector + 图谱扩展、Verifier 微调（自建标注 5k 对）、成本治理（语义缓存 + 小模型路由）。
- **退出标准（第 9 月）**：检索召回 ≥ 82%；单卡成本 ≤ $0.6；可用性 99.5%；无来源断言率 < 2%。
- **紧随其后的商业目标（第 12 月，见 `03` Q4）**：300 WAU、付费 ≥ 60 人、转化 ≥ 5%。
- **风险**：团队被"每个客户都要一个定制功能"撕碎。缓解——功能请求先进"通用性判定"，只有一个客户要的进 backlog 不排期。

### Phase 2 · 规模化 + 产业版（9–18 月）

**目标**：一套底座服务两类客户，且私有化可交付。

- 交付：私有化部署包（Helm + 离线镜像 + 安装校验）；客户内部数据连接器（S3/SharePoint/Confluence/ELN 适配）；团队协作与权限；SOC 2 Type II。
- 技术重点：图谱版本化与"结论翻案"diff 视图；主动学习闭环（在线反馈 → 标注 → 重训）；混合检索的多语言（中英）；成本再降 50%。
- **退出标准**：私有化交付 ≤ 5 人日；单卡成本 ≤ $0.3；判定 F1 ≥ 0.88；2 个企业客户续约。
- **风险**：私有化的运维长尾吃掉整个平台团队。缓解——把私有化当作"产品"而不是"项目"，第一个客户就写安装/升级/回滚剧本。

### Phase 3 · 平台化与公共品（18–36 月）

**目标**：从"工具"变成"基础设施"。

- 交付：开放 Claim Card API（免费额度 + 学术白名单）、公开评测报告、领域扩展（第 3–4 个领域）、实验闭环集成（与 CRO / 自动化实验平台对接）。
- 技术重点：多领域本体治理；跨领域推理的可迁移性；对外 SLA 与配额体系；图谱的增量更新（日更而非全量重建）。
- **退出标准**：外部团队在我们的图谱上构建 ≥ 10 个应用；开放 API 月调用 ≥ 1M；公开发布 ≥ 2 份被引用的评测报告。

## 10. 团队与工程节奏

**Phase 0（6–8 人）**：2 后端/平台、1 数据工程、1 ML/评测、1 研究工程（做 Verifier）、1 领域专家（必须是真做过该领域研究的人）、0.5 设计、创始人 1。

**扩张顺序（每条都对应一个不可外借的能力）**：领域专家 → 评测/标注负责人 → 私有化/基础设施 → 前端体验 → 数据合作/BD。

**节奏**

- 双周：一次 **Eval Review**（只看指标与失败样本，产品会另开）。这是唯一不能被挤掉的会。
- 每月：一次 RFC 评审（架构级变更必须有书面提案与替代方案）。
- 每季：一次 **Kill Review**（见 `03`），对每个方向做继续/转向/停止的显式决定。

**技术债禁区（永远不欠）**：provenance 字段、租户隔离、审计日志、模型调用抽象层、评测门禁。这五项一旦欠债，后期修复成本是重写。

## 11. 成本模型（决定我们是否是奢侈品）

单张 Claim Card 的成本拆解（目标 Phase 2）：

| 项 | 占比 | 优化手段 |
|---|---|---|
| 检索与 rerank | 25% | 预计算段落嵌入；缓存热门实体子图 |
| 判定（小模型） | 20% | 自托管推理；批处理 |
| 生成与解释（大模型） | 40% | 只在不确定区调用；结构化输出减少 token |
| 存储与解析 | 15% | 冷热分层；解析结果复用（同一 DOI 永不重解析） |

> 若单卡成本无法降到 $0.5 以下，P1 的学术定价模型就不成立——**成本是一等产品约束，不是财务问题。**

---

## 12. 三个"如果发生就重写架构"的触发器

1. **前沿模型原生提供可验证的段落级引用且准确率 > 95%**：我们的检索层价值大幅下降，必须把重心彻底移到图谱、冲突建模与工作流上。
2. **客户要求 100% 本地模型（含判定模型）**：那么 Verifier 必须从一开始就是可自托管的小模型——这会影响 Phase 0 的选型，需要在 Phase 0 就留出接口。
3. **语料许可环境收紧（大规模文本许可被禁）**：转向"客户自带 + 机构授权 + 开放获取"三源模型，并强化私有化，我们的商业模型会更像企业软件而非 SaaS。
